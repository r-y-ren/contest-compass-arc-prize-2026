# ARC-AGI-3 自进化智能体复现（复现优先）

## 工作流程

程序的整体流程分四段：

1. **起推理服务**：先在远端 GPU 机器上用 vLLM 把一个 27B 的开源大模型（量化到 FP8）作为常驻服务跑起来。本地程序通过 HTTP 请求它的推理能力——相当于"大脑"放在远端，"手脚"在本地。
2. **接入官方游戏环境**：从官方文档（docs.arcprize.org）拿到 ARC-AGI-3 的开发工具包，连上游戏环境。每一局游戏会不断给程序"看到的东西"（当前局面），程序要在每一步回答"下一步做什么"，直到通关、失败或超时。
3. **跑对照实验**：本地评测脚本按同一批游戏、同一随机种子，分别用四种配置各跑一遍——①什么都不加的裸模型、②加"课程调度"（先易后难地安排练习局）、③加"经验正则"（把过往经验筛选后再利用）、④两个都加。跑完输出一张对照表：四种配置各自赢了多少局。复现是否成功，就看加组件后赢的局数是否按论文方向变化，且重跑一遍结论不变。
4. **打包提交**：把效果最好的配置按比赛要求的格式打包，通过 Kaggle 命令行交到赛站；同时写一份复现报告，报告里每个数字都能找到对应的运行记录文件。

异常处理分两种场合：做对照实验时遇到任何异常（服务掉线、显存不足、非法动作）立即停下报错——因为实验数字必须干净；正式提交评测的跑批里则先重试几次、不行就降级继续并把异常写进日志——因为榜单成绩要保住。所有过程日志都会完整落盘。

## 项目功能

- **对局功能**：接上官方环境后，程序能自己玩 ARC-AGI-3 的游戏——看局面、想下一步、执行动作、记录全过程。
- **裸基线**：一个只靠固定提示词驱动的 27B 模型智能体，作为一切对比的起点。
- **课程调度组件**：复现自 ActiveSaddler 论文的思路（降级实现：作用在练习安排层，不动模型权重）——让智能体按先易后难的顺序积累经验。
- **经验正则组件**：复现自 RRSI 论文的思路（降级实现：作用在经验记忆层，不动模型权重）——把过往经验筛过再喂给模型，抑制越玩越乱。
- **A/B 评测**：一条命令跑出四种配置的对照表，同局同种子，保证数字可比。
- **提交件**：按赛站要求打包好的参赛文件，可用 Kaggle 命令行直接提交。
- **复现报告**：人能读的总结，写清楚每个组件带来了什么变化、数字出自哪次运行。
