# 需求文档：ARC-AGI-3 自进化智能体复现（复现优先）

## 根本目的

复现验证前沿"自进化 agent 栈"（ActiveSaddler 课程调度 + RRSI 经验更新正则，均为官方可跑 demo 卡）在 ARC-AGI-3 交互基准上的增益，挂本地开源 27B FP8 模型（vLLM 远端服务化），以 2026-11-02 终交为目标能交则交。成功长什么样：**A/B 对照表中加组件相对裸基线的增益方向与论文一致、两次独立运行同向、每个数字可溯源到运行产物**；Kaggle 提交成功接收为附加成果而非成功前提。（用户 2026-10-10 grill 确认：复现优先，纯学习定位，无复投诉求。）

## 环境与技术栈决策

| 项 | 决策 |
|---|---|
| 语言/运行时 | Python 3.12，venv 隔离；Linux（远端 GPU 机 + 本机调度） |
| 环境/SDK | ARC-AGI-3 官方 SDK（docs.arcprize.org；包名与接口形态待 scaffold 期实核定，grill 时页面未展开） |
| 推理服务 | vLLM 起本地服务承载 27B FP8（远端 remote-compute GPU），agent 经 HTTP 调用；不训权重（一期） |
| 错误处理风格 | 显式错误码 + 有限重试；分场景哲学（见边界节） |
| 日志方式 | JSONL 文件 + 控制台双路；每步 obs/action/耗时全量落盘 |

（fn-grill 2026-10-10 用户确认：vLLM 服务化方案。）

## 术语表

| 术语 | 精确定义 |
|---|---|
| 局（episode） | ARC-AGI-3 的一次完整交互游戏，从初始观测到通关/失败/超时 |
| 观测（obs） | SDK 在每步给 agent 的局面信息 |
| 动作（action） | agent 每步返回的合法操作；非法动作由 SDK 拒绝并返回错误码 |
| 裸基线 | 冻结 27B + 固定提示词，无任何自进化组件的 agent |
| 课程调度（降级实现） | ActiveSaddler 思路作用于练习局编排层（先易后难选择经验来源），不动权重 |
| 经验正则（降级实现） | RRSI 思路作用于经验记忆层（筛选/正则化历史经验再入提示），不动权重 |
| 训练环 | 对权重做更新的完整复现路径——**二期可选，本期范围外** |
| 失败模式（failure mode） | ActiveSaddler 术语：一类可复用的失败原因（臂），LLM 按 severity/fixability/breadth/side-effect 四因子打分 φ_t∈[0,1] |
| 臂（arm）/ 拉臂 | bandit 术语：课程调度的候选练习目标；softmax(φ_t/温度) 概率选择 |
| 提示编辑流 | RRSI 术语：以『对提示的原子编辑』为单位的经验记录（编辑内容/假设/效果/采纳否），替代局级经验摘要 |
| 编辑预算（L0 式） | RRSI 正则：入提示的编辑条数上界 b_t，随轮次余弦退火收紧（如 3-4→1） |
| 帧差异提示 | 观测表征增强：把前后帧有变化的单元格坐标列表写进提示（首步/无变化时空节） |
| A/B 对照 | 同局集同种子下 ≥2 种配置的评测对比 |
| 评测跑批（提交用） | 为生成 Kaggle 提交结果的全量运行（异常处置=降级继续） |
| 复现实验 | 为产出可信增益数字的运行（异常处置=失败即停） |

## 需求条目

### R1 官方环境接入与对局循环 [P0]
- 内容：接入 ARC-AGI-3 官方 SDK；实现 obs→LLM→action 主循环。输入=SDK 观测流；输出=每步合法 action + 局终状态；错误=非法动作/超时按 SDK 错误码记录。
- 验收方式：命令化——评测入口以指定局集跑 N≥20 局零未捕获异常；JSONL 日志含每步 obs 摘要/action/耗时；局终状态字段完整。

### R2 裸 27B 基线 agent [P0]
- 内容：vLLM 服务 + 固定提示词的最小 agent。输入=观测；输出=action；错误=服务不可达时按场景哲学处置。
- 验收方式：命令化——`eval_ab.py --config baseline --episodes N --seed S` 产出成功率与平均步数，两跑同配置数字可复现（同 seed 一致）。

### R3 课程调度组件（降级实现）[P0]
- 内容：按 ActiveSaddler 思路实现练习/经验编排（组件仓 fork 冻结 commit 引用其可复用件）。输入=局历史与难度信号；输出=下一经验源选择。
- 验收方式：命令化——A/B 表中 baseline+R3 相对 baseline 的成功率变化方向有输出；组件决策每步落日志可查。

### R4 经验正则组件（降级实现）[P0]
- 内容：按 RRSI 思路实现经验筛选/正则化入提示（fork 冻结引用）。输入=历史经验流；输出=入提示的经验子集。
- 验收方式：同 R3 形态（A/B 表 + 决策日志）。

### R5 A/B 评测脚本 [P0]
- 内容：`eval_ab.py`——同局集同种子跑 ≥4 配置（baseline / +R3 / +R4 / 全开），输出统一对照表（CSV+控制台）。错误=实验态失败即停（R1-R4 评测均经此脚本）。
- 验收方式：命令 + 期望输出两级制——`python eval_ab.py --episodes N --seed S` 输出四行对照表；判据=两次独立运行增益方向一致。

### R6 Kaggle 可提交 agent 包 [P0]
- 内容：按赛站契约打包最优配置（提交态异常=有限重试→降级继续）。
- 验收方式：命令化——starter kit notebook 组装并推送（`make submit` → `kaggle kernels push`）成功，网页 "Submit to Competition" 后赛站页面可查接收记录（契约实核见 references/kaggle_competition_contract.md；2026-10-11 修订，原 `-f` 直接提包形态为计划期假定）

### R7 复现报告 [P0]
- 内容：增益表 + 配置说明 + 每个数字的运行产物路径（`fn_work/runs/`）。
- 验收方式：可观察判据——报告读者/审阅者按路径能找到对应运行产物且数字一致（谁看/看什么/什么算对三要素）。

### R8 包装策略钩子转发修复 [P0]（演进周期①，2026-10-12）
- 内容：CurriculumPolicy/RegularizedPolicy 的 on_episode_start/on_episode_end 检测到内层策略有同签名钩子即转发（先外后内定序并在 docstring 钉死）；修复前 inner RegularizedPolicy 经验库永不写入（full 组合 no-op，token 证据：384311==384311）。
- 验收方式：命令化——①pytest 新增三层嵌套单测（断言内层钩子被调、时序确定）；②tower 27B 实跑 full 与 plus_curriculum 各一次，token_usage 不再相同。

### R9 提示动态性增强（步号+动作历史+帧差异） [P0]（演进周期①，2026-10-12）
- 内容：build_baseline_prompt 在观测视图外加动态槽位——步数编号、最近 K=5 步动作回显（动作名+坐标）、前后帧变化单元格坐标列表（首步或无变化=空节）；模板仍为常量（含固定槽位语法），槽位由代码填充。R2『固定提示词』措辞随此微调为『固定模板+动态槽位』（变更记录）。
- 验收方式：命令化——27B 冒烟脚本（单局 20 步）断言：动作坐标去重数≥3/20 步；提示文本含步号与帧差异节标记；pytest 单测覆盖首步空差异/K 步截断/槽位确定性。

### R10 局集与局量扩展 + Kaggle 免费 GPU 探索 [P0]（演进周期①，2026-10-12）
- 内容：episode_sets 扩至分层局集（匿名可玩 25 局中分层选取，保留 vc33/cd82 对照），跑批 N=20（R1 口径）；附带探索：Kaggle rtx6000（赛站专属加速器）承载 vLLM 27B FP8 + 本评测栈的可行性（配额/时长/断网评测约束），产出可行性记录落 fn_docs/results/，不阻塞 tower 主线；若可行登记为免费 FP8 口径算力通道。
- 验收方式：两级制——命令优先：eval_ab --episodes 20 --seed S 产出四配置对照表（CSV+stdout）；判据补充：baseline wins≥1（若仍 0，如实记录并附每局结局分布，增益信号判定顺延）；Kaggle 探索产出 results/ 可行性记录一件。

### R11 组件机制对齐论文重设计（fork 复用官方仓代码件） [P0]（演进周期①，2026-10-12）
- 内容：结构性重设计 R3/R4 子树——课程侧按 ActiveSaddler：失败模式为臂、局终由 LLM 打分 φ_t（四因子，1 次额外调用/局，LLM 失败时默认 φ=0.5 低置信）、softmax 温度拉臂、臂可动态新增（不删只衰减）；正则侧按 RRSI：经验=提示编辑流（原子编辑记录）、入提示条数受 L0 预算约束（余弦退火）、泄漏检查（拒把『答案性内容』直写提示）。microsoft/AutoSaddler 与 google-research RRSI 官方仓 fork 冻结 commit 引入可复用代码件（外部依赖登记）；函数树经 fn-divide 重排，R1/R2/R5-R7 契约不动。
- 验收方式：两级制——命令优先：①组件决策 JSONL 事件含 φ_t 打分记录/拉臂选择理由/编辑预算消耗计数；②eval_ab N=6 对照表四行产出且组件行与 baseline 行 token_usage 不同；判据补充：增益方向与论文一致（组件≥baseline），或如实记录反向并回 fn-analyze。

（P1 备选池：训练环完整复现——用户明示二期可选，不进本期排期。）
