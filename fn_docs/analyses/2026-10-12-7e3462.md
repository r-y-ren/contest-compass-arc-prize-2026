- **结果轴**：①双跑 wins/steps/token 逐项一致——R2/R5 确定性与同向验收成立；②四配置全 0 胜、avg_steps=75.0（地板效应，增益方向零分辨率不可测）；③冒烟局 ACTION6(10,10)×20 零多样性、obs_summary 20 步逐字段相同、延迟 1786-2599ms；④**plus_curriculum 与 full 的 token 完全相同（384311/1250）**——full 组合中经验正则层零行为差异。
- **代码机械轴**：fn-check 全量 246 passed、桩 0——数据差非代码坏；doc-lint 43 错（批注式状态词/B1 行未删等文档卫生债，不阻断、另册登记）。
- **职责关联轴**（软件缺陷类，走职责链）：
  - 现象④ → CurriculumPolicy 职责"包装内层策略：局内行为转发内层"——**钩子（on_episode_start/end）未转发内层**，内层 RegularizedPolicy 的经验库永不写入 → act 时子集恒空 → no-op。嫌疑人=make_curriculum_policy.py（RegularizedPolicy 同理，层数再多也断在第一层）。
  - 现象③ → build_baseline_prompt/render_obs 职责"观测→提示词视图"——视图仅当前帧（2500 字符截断），无步号/无动作历史回显；游戏状态不变+贪心解码 → 提示每步近似相同 → 输出锁死。嫌疑=观测表征动态性不足（叠加 temperature=0 无探索）。
  - 现象② → eval_ab/load_episode_set 局集口径：N=2+难局（vc33/cd82 点击局）不足以让 baseline 非零。

## 论文实抓要点（对齐缺口）

- **ActiveSaddler**（arXiv:2610.00906，microsoft/AutoSaddler 233★）：失败模式驱动的**非平稳 bandit 课程**——LLM 对失败模式臂打分 φ_t∈[0,1]（severity/fixability/breadth/side-effect 四因子）、温度 0.15 softmax 拉臂、臂由 LLM 两段抽象动态增（复用/组合/新建）。**本项目"难度标量+score min 先易后难"为其意译降级**。
- **RRSI**（arXiv:2609.24972，google-research）：**harness 编辑流正则**——原子编辑级经验记忆（组件/假设/diff/ΔS/ΔC/采纳否）、提案端余弦退火编辑预算（L0 式 ≤b_t，3-4→1）、泄漏 critic+剪枝 pruner。**本项目"历史局经验筛选入提示"为其意译降级**。
- 前言补充：Milestone #1 冠军=Qwen 27B FP8 于 Kaggle 免费 GPU（rtx6000）——FP8 口径的合规路径在赛站侧，不在本地 24G；Memento 3（全清 25 关，无码）可作观测表征设计参考。

## 改进提案（均已登记 registry.jsonl）

### P1 观测链验证与提示动态性增强 [高]（参数/逻辑级 [改造]）
- 现象：冒烟 20 步 obs_summary 逐字段相同+模型贪心复读 (10,10)，token 2648/步。
- 假设：build_baseline_prompt 职责是"拼装观测视图入提示"，而视图无步号/无近期动作历史——状态不变时提示恒定，贪心输出锁死；0 胜部分源于此（而非纯模型能力）。
- 改进方向：先 dump 单步完整 prompt 证实状态变化是否到达模型；然后提示中加入步号与最近 K 步动作回显（破除重复锁死），必要时观测渲染压缩（网格变化单元格/色彩图例）。
- 预期信号：27B 冒烟动作坐标多样性>1（去重数≥3/20 步）、非回退动作占比>0；若状态确实不变，动作历史仍应驱动探索。
- 分流：[改造] build_baseline_prompt（+render_obs 如需）。

### P2 包装策略钩子转发修复 [高]（参数/逻辑级 [改造]，真缺陷）
- 现象：plus_curriculum 与 full 双跑 token 完全相同（384311/1250）。
- 假设：CurriculumPolicy 的职责含"包装内层策略"，但其 on_episode_start/end 只更新自身难度史、不转发内层——内层 RegularizedPolicy 经验库永不写入（full 组合断在第一层）。
- 改进方向：两包装策略的钩子转发内层同签名钩子（存在即调）；补三层嵌套单测。
- 预期信号：修复后 full 与 plus_curriculum 的 token 不再相同；单测断言内层钩子被调。
- 分流：[改造] make_curriculum_policy.py / make_regularized_policy.py。

### P3 局集与局量扩展 [中]（配置级）
- 现象：四配置全 0 胜（2 局×点击类难局），增益列零分辨率。
- 假设：eval_ab 局集口径 N=2+vc33/cd82 不足以产生非零 baseline；匿名可玩 25 局在库。
- 改进方向：扩 episode_sets 至更多/更易局（keyboard_click/click 之外试其它 tag），局量 N≥20（R1 口径），用 tower 27B 跑批看 baseline 非零。
- 预期信号：baseline 胜率>0（任一配置 wins≥1）；A/B 增益列出现非零值。
- 分流：配置与数据级（episode_sets/default.yaml + 跑批参数），不动函数结构。

### P4 组件机制对齐论文重设计 [激进]（结构性 → fn-divide）
- 现象：论文实抓显示两组件的原机制（失败模式 bandit / 编辑流 L0 正则+泄漏 critic）与当前降级实现（静态难度 min 选择 / 局级经验筛选）差异大；前言载官方仓可跑（AutoSaddler 233★、google-research RRSI）可 fork 冻结复用。
- 假设：证据链——降级实现的增益上限受机制保真度限制；若 P1-P3 后 baseline 非零而组件增益仍≈0，需按论文机制重设计（LLM 失败模式打分替代标量难度；编辑流预算替代容量淘汰）。
- 改进方向：克隆两官方仓提炼可复用件（fork 冻结 commit），课程臂=失败模式、正则=提示编辑预算；经 fn-divide 重排 R3/R4 子树。
- 预期信号：组件决策日志出现失败模式打分与编辑预算消耗；A/B 增益方向与论文一致（组件>baseline）。
- 分流：结构性——回 fn-divide（演进周期开 R 条目）。
